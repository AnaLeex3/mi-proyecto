# Portafolio de pruebas de software (QA)

Repositorio de práctica para el diseño, la organización y el control de versiones de artefactos de prueba. Reproduce el flujo de trabajo de un equipo de QA utilizando Git y GitHub.

## Contenido

| Carpeta | Descripción |
|---|---|
| `plan/` | Plan de pruebas (PLAN-001) |
| `casos-de-prueba/` | Casos de prueba con precondiciones, pasos y resultado esperado (TC-LOGIN-001, TC-LOGIN-002) |
| `defectos/` | Reportes de defectos (BUG-001, ejemplo de práctica) |

## Técnicas y conceptos aplicados

- Diseño de casos de prueba de caja negra (partición de equivalencia, valores límite)
- Trazabilidad entre casos de prueba y defectos
- Criterios de entrada y salida en el plan de pruebas
- Control de versiones: commits, ramas, merge y resolución de conflictos de sincronización

## Convenciones

- **Identificadores únicos:** `PLAN-###`, `TC-MODULO-###`, `BUG-###`
- **Formato:** todos los artefactos están en Markdown
- **Commits:** mensajes breves que describen el cambio realizado, por ejemplo "Agrega caso de prueba TC-LOGIN-002"

## Alcance

Los artefactos corresponden a un módulo de login ficticio y tienen fines de práctica. El reporte BUG-001 es un ejemplo que ilustra el formato de un defecto.
